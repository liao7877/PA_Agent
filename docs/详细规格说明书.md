## 1. 产品需求规格

### 1.1 产品定义

| 属性 | 规格 |
|------|------|
| 产品名称 | Trading Agent / PA_Agent |
| 产品类型 | 单进程 Windows 桌面应用 |
| 目标用户 | 主观价格行为交易者 |
| 核心价值 | 将「看图」结构化为可复核的两阶段 AI 决策路径 |
| 排除范围 | 券商连接、自动下单、截图识图、投资建议背书 |

### 1.2 功能需求清单

#### FR-01 实时 K 线展示

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-01.1 | 从可配置数据源拉取 OHLCV | MT5 / TradingView / yfinance / AkShare 可切换 |
| FR-01.2 | 默认定时刷新 | `general.refresh_interval_ms` 默认 1000 |
| FR-01.3 | 蜡烛图 + EMA20 | pyqtgraph 渲染，指标由 `indicators/ema.py` 计算 |
| FR-01.4 | K 线序号标签 | 已收盘棒显示 #1…#N；未收盘棒空心显示 |
| FR-01.5 | 分析窗口根数可配 | `general.analysis_bar_count`，范围 2–1000，默认 100 |
| FR-01.6 | **图表实时更新开关** | 控制栏可勾选按钮，默认开启；关闭时冻结为纯已收盘帧 |

#### FR-02 两阶段 AI 分析

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-02.1 | 用户手动触发 | 「提交分析」按钮，非自动交易 |
| FR-02.2 | Stage 1 市场诊断 | 输出符合 `STAGE1_SCHEMA` 的 JSON |
| FR-02.3 | 策略文件路由 | 根据 Stage1 输出动态加载 `prompt_engineering/*.txt` |
| FR-02.4 | Stage 2 交易决策 | 输出符合 `STAGE2_SCHEMA` 的 JSON |
| FR-02.5 | 闸门短路 | `gate_result ∈ {wait, unknown}` 时跳过 Stage2 API |
| FR-02.6 | Preflight 数据门槛 | <20 根已收盘或指标全 NaN 时不调 AI |
| FR-02.7 | 增量分析 | 基于上次成功 record 只分析新增已收盘 K 线 |
| FR-02.8 | 等待收盘 | 可选等待当前 forming bar 收盘后再提交 |
| FR-02.9 | 校验失败重试 | `validation_retry` 可配置重试次数与策略 |

#### FR-03 JSON 校验与归一化

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-03.1 | 五级错误分类 | category a（语法）/ b / c / d / e |
| FR-03.2 | Schema 校验 | `jsonschema` + `prompts/schemas.py` |
| FR-03.3 | 字段归一化 | `normalize_stage1/2()` 修正别名与缺省 |
| FR-03.4 | 一致性校验 | `coherence_checks`：gate_trace vs decision 字段 |
| FR-03.5 | 可选 trace 语义校验 | `validation.trace_semantic_checks` |
| FR-03.6 | 不下单 invariant | `order_type=不下单` 时价格字段必须为 null |
| FR-03.7 | 截断 JSON 修复 | `resolve_stage_json_text` 尝试补全截断响应 |

#### FR-04 GUI 与交互

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-04.1 | 主布局 | 左图表 + 右 AI 侧栏（QSplitter） |
| FR-04.2 | 侧栏多 Tab | 实时/决策流/可视化/决策/未来走势/原始/调试 |
| FR-04.3 | 决策 overlay | 入场/止损/止盈水平线（非「不下单」时） |
| FR-04.4 | 图表实时更新可切换 | 见 FR-01.6；分析中可保持开启 |
| FR-04.5 | 设置对话框 | Provider、通用、通知、跟踪时段 |
| FR-04.6 | 演示模式 | 回放 `records/pending/` 历史，无需 API |
| FR-04.7 | 决策树可视化 | `decision_flow_viz` 可交互路径动画 |
| FR-04.8 | API 健康检测 | 设置页可探测 Provider 连通性 |

#### FR-05 图表实时更新（详细行为）

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-05.1 | 默认可勾选开启 | `_resume_chart_btn.setCheckable(True)`，`setChecked(True)` |
| FR-05.2 | 关闭时冻结 | `_on_chart_live_toggle(False)` → 纯已收盘帧 + `_chart_refresh_paused=True` |
| FR-05.3 | 开启时恢复 | `_on_chart_live_toggle(True)` → 恢复 RefreshLoop + `refresh_chart_once` |
| FR-05.4 | 分析开始条件冻结 | 仅当 `not _chart_live_updates_enabled()` 时 `set_frame_now` 分析帧并暂停 |
| FR-05.5 | 分析中可保持实时 | 开关开启时分析进行中图表继续显示 forming bar |
| FR-05.6 | 追问快照 | `snapshot_klines_for_followup`：live_on 时不强制冻结；导出表仍仅已收盘 |
| FR-05.7 | 分析后自动恢复 | `general.auto_resume_chart_after_analysis` 或 `keep_analysis` 触发恢复 |
| FR-05.8 | 状态栏提示 | 分析中显示「图表实时更新已开启」或「图表已冻结」 |

#### FR-06 通知

| ID | 需求 | 验收标准 |

| FR-06.1 | 钉钉 Webhook | `notification.dingtalk_*` 配置后可推送 |
| FR-06.2 | Bark | `notification.bark_*` 配置后可推送 |

| FR-06.4 | API 失败通知 | `notify_api_failure` 在分析/追问异常时推送 |

#### FR-07 持仓跟踪

|----|------|----------|

| FR-07.3 | 持久化 | `PositionStore` 本地存储 |

#### FR-08 跟踪时段

| ID | 需求 | 验收标准 |

| FR-08.3 | UI 状态 | 非跟踪时段显示提示标签 |

#### FR-09 授权（打包版）

## 2. 非功能需求

| ID | 类别 | 规格 |
|----|------|------|
| NFR-01 | 平台 | Windows 10/11 为主；macOS 部分支持（API Key 加密路径不同） |
| NFR-02 | Python | ≥ 3.11 |
| NFR-03 | 响应性 | 分析在后台 QThread，不阻塞 UI 事件循环 |
| NFR-04 | 安全 | API Key DPAPI（Win）/ cryptography（macOS）加密存储 |
| NFR-05 | 可观测性 | `logs/pa_agent.log`；流式 token 在侧栏实时显示 |
| NFR-06 | 可测试性 | unit / integration / property 测试覆盖核心校验与编排 |

## 3. 接口与数据契约

### 3.1 Stage1 输出（摘要）

关键字段：`cycle_position`、`direction_bias`、`gate_result`、`detected_patterns`、`bar_by_bar_summary`。

### 3.2 Stage2 输出（摘要）

关键字段：`decision`、`order_type`、`entry_price`、`stop_loss`、`take_profit`、`gate_trace`、`decision_trace`、`next_bar_prediction`。

### 3.3 K 线帧语义

| 类型 | 组成 | 用途 |
|------|------|------|
| `build_live_frame` | N 已收盘 + 可选 1 forming | 图表实时显示 |
| `build_analysis_frame` | 仅 N 已收盘 | AI 分析、冻结图表 |
