## 1. 产品需求规格

### 1.1 产品定义

| 属性 | 规格 |
|------|------|
| 产品名称 | Trading Agent / PA_Agent |
| 产品类型 | 单进程 Windows 桌面应用 |
| 目标用户 | 主观价格行为交易者 |
| 核心价值 | 将「看图」结构化为可复核的两阶段 AI 决策路径 |
| 排除范围 | 券商连接、自动下单、截图识图、投资建议背书 |

### 1.2 功能需求清单

#### FR-01 实时 K 线展示

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-01.1 | 从可配置数据源拉取 OHLCV | MT5 / TradingView / AkShare 可切换 |
| FR-01.2 | 默认 1Hz 刷新 | `general.refresh_interval_ms` 默认 1000 |
| FR-01.3 | 蜡烛图 + EMA20 | pyqtgraph 渲染，指标由 `indicators/ema.py` 计算 |
| FR-01.4 | K 线序号标签 | 已收盘棒显示 #1、#3…；未收盘棒空心显示 |
| FR-01.5 | 分析窗口根数可配 | `general.analysis_bar_count`，范围 20–5000，默认 100 |

#### FR-02 两阶段 AI 分析

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-02.1 | 用户手动触发 | 「提交分析」按钮，非自动交易 |
| FR-02.2 | Stage 1 市场诊断 | 输出符合 `STAGE1_SCHEMA` 的 JSON |
| FR-02.3 | 策略文件路由 | 根据 Stage1 输出动态加载 `prompt_engineering/*.txt` |
| FR-02.4 | Stage 2 交易决策 | 输出符合 `STAGE2_SCHEMA` 的 JSON |
| FR-02.5 | 闸门短路 | `gate_result ∈ {wait, unknown}` 时跳过 Stage2 API |
| FR-02.6 | Preflight 数据门槛 | <20 根已收盘或指标全 NaN 时不调 AI |
| FR-02.7 | 增量分析 | 基于上次成功 record 只分析新增已收盘 K 线 |
| FR-02.8 | 等待收盘 | 可选等待当前 forming bar 收盘后再提交 |

#### FR-03 JSON 校验与归一化

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-03.1 | 五级错误分类 | category a（语法）/ b / c / d / e |
| FR-03.2 | Schema 校验 | `jsonschema` + `prompts/schemas.py` |
| FR-03.3 | 字段归一化 | `normalize_stage1/2()` 修正别名与缺省 |
| FR-03.4 | 一致性校验 | `coherence_checks`：gate_trace vs decision 字段 |
| FR-03.5 | 可选 trace 语义校验 | `validation.trace_semantic_checks` |
| FR-03.6 | 不下单 invariant | `order_type=不下单` 时价格字段必须为 null |

#### FR-04 GUI 与交互

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-04.1 | 主布局 | 左图表 + 右 AI 侧栏（QSplitter） |
| FR-04.2 | 侧栏 7 Tab | 实时/决策树/可视化/决策/未来走势/原始/调试 |
| FR-04.3 | 决策 overlay | 入场/止损/止盈水平线（非「不下单」时） |
| FR-04.4 | 分析中暂停刷新 | 避免界面数据与提交快照不一致 |
| FR-04.5 | 设置对话框 | Provider、通用、通知三大页 |
| FR-04.6 | 演示模式 | 回放 `records/pending/` 历史，无需 API |

#### FR-05 分析后追问（Free Chat）

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-05.1 | 分析完成后可追问 | `FreeChatSession` |
| FR-05.2 | 冻结图表数据 | 追问前刷新一次再冻结，与屏幕 K 线表一致 |
| FR-05.3 | 追问落盘 | `.followups.jsonl` sidecar |

#### FR-06 记录与经验库

| ID | 需求 | 验收标准 |
|----|------|----------|

| FR-06.3 | API Key 脱敏 | `pending_writer` 递归 mask |
| FR-06.4 | 经验库只读注入 | `experience/{cycle}/{success\|failure}_cases/` |
| FR-06.5 | 用户手动归类 | 程序不写 experience，用户搬移 pending |

#### FR-07 通知与持仓跟踪

| ID | 需求 | 验收标准 |
|----|------|----------|
| FR-07.1 | 钉钉 / Bark 推送 | `notification/channels.py` |

#### FR-08 授权（打包版）

| ID | 需求 | 验收标准 |

| FR-08.1 | Ed25519 签名验证 | `licensing/crypto.py` |

## 2. 系统架构规格

### 2.1 逻辑分层

```
┌─────────────────────────────────────────────────────────┐
│  Presentation（PyQt6 主线程）                            │
│  MainWindow / ChartWidget / AISidebar / SettingsDialog  │
├─────────────────────────────────────────────────────────┤
│  Application（后台 QThread）                             │
│  RefreshLoop / _AnalysisWorker / SnapshotWorker         │
├─────────────────────────────────────────────────────────┤
│  Domain                                                  │
│  TwoStageOrchestrator / FreeChatSession / PositionTracker│
├─────────────────────────────────────────────────────────┤
│  Infrastructure                                          │
│  DataSource / DeepSeekClient / PendingWriter / Notifier │
└─────────────────────────────────────────────────────────┘
```

### 2.2 线程模型

| 线程 | 组件 | 规则 |
|------|------|------|
| 主线程 | 所有 QWidget、图表绘制 | UI 更新仅通过 signal/slot |
| RefreshLoop QThread | 定时 `latest_snapshot()` | 结果 signal 到 MainWindow |
| _AnalysisWorker QThread | `TwoStageOrchestrator.submit()` | `OrchestratorEvent` 回调更新 UI |
| 通知 HTTP | `NotificationService` 内异步 | 不阻塞分析主路径 |

### 2.3 依赖注入

`AppContext` 承载全部共享依赖，**禁止**在业务模块内 `load_settings()` 或新建全局 Client。

## 3. 接口规格

### 3.1 DataSource 抽象接口

```python
# pa_agent/data/base.py

class DataSource(ABC):
    def connect(self) -> None: ...
    def disconnect(self) -> None: ...
    def list_symbols(self) -> list[str]: ...
    def supported_timeframes(self) -> list[str]: ...
    def subscribe(self, symbol: str, timeframe: str) -> None: ...
    def unsubscribe(self) -> None: ...
    def latest_snapshot(self, n: int) -> list[KlineBar]: ...
```

**KlineBar 约定**：
- `list[0]` = 时间最新的一根（可含 forming bar）
- 字段：open, high, low, close, volume, time, is_closed

### 3.2 DeepSeekClient

```python
# pa_agent/ai/deepseek_client.py

def stream_chat(
    messages: list[dict],
    *,
    on_chunk: Callable[[str, str], None] | None,  # (kind, text) kind: content|reasoning
    cancel_token: CancelToken | None,
) -> AIReply  # content, reasoning_content, usage, latency_ms
```

**配置映射**：
- `provider.thinking` → 是否传 reasoning 相关参数
- `provider.reasoning_effort` → low|medium|high|max

### 3.3 TwoStageOrchestrator.submit()

```python
def submit(
    frame: KlineFrame,
    *,
    cancel_token: CancelToken,
    on_event: Callable[[OrchestratorEvent], None],
    htf_text: str = "",
    previous_record: AnalysisRecord | None = None,  # 增量模式
    incremental: bool = False,
) -> AnalysisRecord
```

**OrchestratorEvent 类型**（部分）：
- `Stage1Started`, `Stage1Chunk`, `Stage1Done`, `Stage1Failed`
- `Stage2Started`, `Stage2Chunk`, `Stage2Done`, `Stage2Failed`
- `RecordSaved`, `InsufficientData`, `UserCancelled`

### 3.4 JsonValidator

```python
def validate(stage: Literal["stage1", "stage2"], raw_text: str, *, settings: Settings) -> Ok | ValidationError
```

**处理流水线**：
1. 去 markdown fence
2. `json.loads`（category a）
3. jsonschema（category b/c）
4. `normalize_stage1/2`
5. `coherence_checks` + 可选 `trace_semantic_checks`

### 3.5 route_strategy_files

```python
def route_strategy_files(stage1_json: dict[str, Any]) -> list[str]
```

**纯函数**，无副作用，输入输出确定性（有 property 测试覆盖）。

## 4. 数据规格

### 4.1 AnalysisRecord（canonical）

见 `pa_agent/records/schema.py`，`extra="forbid"`。

**文件名规则**：`{timestamp_local_iso 格式化}_{symbol}_{timeframe}.json`  
示例：`2026-06-13_12-06-47_BTCUSD_15m.json`

### 4.2 Stage 1 诊断 JSON（核心字段）

| 字段 | 说明 |
|------|------|
| `cycle_position` | micro_channel / tight_channel / trading_range / spike / ... |
| `direction` | bullish / bearish / neutral |
| `gate_result` | pass / wait / unknown |
| `gate_trace` | 闸门决策路径节点数组 |
| `bar_by_bar_summary` | 逐 K 摘要列表 |
| `detected_patterns` | 形态标签数组 |
| `entry_setup_type` | 入场设置类型 |
| `diagnosis_confidence` | 诊断置信度 |

完整 schema：`pa_agent/ai/prompts/schemas.py` → `STAGE1_SCHEMA`

### 4.3 Stage 2 决策 JSON（核心字段）

| 字段 | 说明 |
|------|------|
| `decision` | trade / no_trade |
| `order_type` | 限价单 / 突破单 / 市价单 / 不下单 |
| `order_direction` | long / short |
| `entry_price`, `stop_loss`, `take_profit` | 价格或 null |
| `decision_trace` | 决策路径节点数组 |
| `trade_confidence` | 交易置信度 |
| `position_action` | new / hold / close / ... |
| `next_bar_prediction` | 下一根 K 预测对象 |
| `signal_bar`, `entry_bar` | K 线序号引用 |

### 4.4 K 线提交格式（文本表）

由 `PromptAssembler` 生成，包含：
- OHLCV 列
- EMA20、ATR14
- 几何特征列（`kline_features.py`）
- 序号列（K1 = 最新已收盘）

## 6. 提示词工程规格

### 6.1 文件分类

| 类型 | 加载时机 | 示例 |
|------|----------|------|
| 常驻人设 | Stage1+2 system | `提示词大纲_人设与思维方式.txt`、`二元决策.txt` |
| Stage1 任务 | Stage1 user 固定 | `市场诊断框架.txt`、`逐棒分析检查单.txt` |
| Stage2 策略 | 路由动态 | `上涨通道交易策略.txt`、`文件14-楔形形态分析交易.txt` |
| 参考（不注入） | — | `_reference/pattern_enum.md` |

### 6.2 路由表（摘要）

| cycle_position | direction | 基座文件 |
|----------------|-----------|----------|
| channel 类 | bullish | 上涨通道分析识别 + 交易策略 + 文件13 |
| channel 类 | bearish | 下跌通道分析识别 + 交易策略 + 文件13 |
| spike | bullish/bearish | 极速上涨/下跌 分析+策略 |
| trading_range / trending_tr | * | 震荡区间 分析+策略 |
| extreme_tr / unknown | * | **空**（不建议交易） |

**Pattern 叠加**（节选）：wedge→文件14，reversal→文件15，barbwire→文件21，magnet→文件22

## 8. 非功能需求

### 8.1 性能

| 指标 | 目标 |
|------|------|
| 图表刷新 | ≤1s 周期，30Hz 重绘 |
| 分析耗时 | 取决于 LLM；UI 必须保持响应（后台线程） |
| Prompt 缓存 | system prompt `cached_property` 进程级缓存 |

| 项 | 措施 |
|----|------|
| API Key | DPAPI 加密 + 日志脱敏 |

| 许可 | Ed25519 + 机器绑定 + 时钟回拨检测 |

| 层级 | 工具 |

## 11. 附录：错误分类对照

| Category | 含义 | 典型处理 |
|----------|------|----------|
| a | JSON 语法错误 | 记录 partial，Stage1 可能保留部分诊断 |
| b | 缺少必填字段 | 校验失败，落 exception |
| c | 字段值非法（枚举等） | normalizer 尝试修正；失败则报错 |
| d | 非 JSON 纯文本 | Stage2 可注入「不下单」stub |
| e | 一致性/语义错误 | coherence_checks 失败 |
