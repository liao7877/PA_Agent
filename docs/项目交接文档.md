## 2. 业务与领域知识

### 2.1 方法论来源

项目基于 **Al Brooks 风格价格行为学**，提示词资产在 `prompt_engineering/`（约 20+ 个 `.txt` 文件），由程序只读加载，**改策略通常改 txt 而非改 Python**。

### 2.2 两阶段分析语义

| 阶段 | 名称 | 输出 | 作用 |
|------|------|------|------|
| **Stage 1** | 市场诊断 | `stage1_diagnosis` JSON | 周期位置、方向、闸门结果、逐 K 摘要、检测到的形态 |
| **Stage 2** | 交易决策 | `stage2_decision` JSON | 是否下单、订单类型、入场/止损/止盈、信号链 trace、`next_bar_prediction` |

**闸门短路**：Stage 1 若 `gate_result` 为 `wait` 或 `unknown`，程序**跳过 Stage 2 API 调用**，直接生成「不下单」决策并落盘。

### 2.3 K 线序号约定（极易踩坑）

- 图表实时模式：最右侧可有**未收盘**空心 K 线
- **提交分析时**：只送**已收盘** K 线；K1 = 最新已收盘棒
- 分析后图表冻结，未收盘棒会消失 — 详见 `docs/图表K线与分析快照说明.md`

## 4. 模块说明（按改造优先级）

### 4.1 启动与装配

| 文件 | 职责 |
|------|------|
| `pa_agent/main.py` | QApplication → 主题 → **许可校验** → `AppContext.bootstrap()` → `MainWindow` |
| `pa_agent/app_context.py` | 一次性装配：Settings、DataSource、DeepSeekClient、PromptAssembler、JsonValidator、PendingWriter、PositionTracker、NotificationService |

**改造建议**：新增全局服务时优先挂到 `AppContext`，避免散落单例。

### 4.2 数据层 `pa_agent/data/`

| 文件 | 类/函数 | 说明 |
|------|---------|------|
| `base.py` | `DataSource`, `KlineBar`, `KlineFrame` | 数据源抽象；index 0 = 最新棒 |
| `factory.py` | `create_data_source()` | `mt5` / `tradingview` / `akshare` |
| `mt5.py` | `MT5Source` | Windows MetaTrader5 官方包 |
| `tradingview.py` | `TradingViewSource` | tvdatafeed WebSocket |
| `akshare_source.py` | `AkShareSource` | A 股，需 `pip install -e ".[ashare]"` |
| `snapshot.py` | `build_analysis_frame()` | 指标预热 50 根 + 分析窗口 N 根 |
| `refresh_loop.py` | `RefreshLoop` | QThread 定时拉取，signal 推 GUI |

**扩展新数据源**：实现 `DataSource` 接口 → 在 `factory.py` 注册 → Settings 增加 `last_data_source` 枚举。

### 4.3 AI 层 `pa_agent/ai/`

| 文件 | 职责 |
|------|------|
| `prompt_assembler.py` | 组装 Stage1/2 messages；注入 K 线表、几何特征、经验库、策略 txt |
| `router.py` | `route_strategy_files(stage1_json)` — 按诊断路由策略文件 |
| `pattern_routing.py` | 从 Stage1 字段补全 `detected_patterns` |
| `json_validator.py` | JSON 提取 → schema → normalizer → coherence → 返回 `Ok` / `ValidationError` |
| `stage1_normalizer.py` | Stage1 字段别名、bar 标签、gate 推断 |
| `stage2_normalizer.py` | 不下单清价格字段、next_bar_prediction、trade_metrics |
| `trace_normalize.py` | gate_trace / decision_trace 节点格式统一 |
| `coherence_checks.py` | 口头方向 vs JSON 字段交叉校验 |
| `decision_nodes.py` | **PreflightDataGate**（AI 前数据门槛）、确定性决策节点引擎 |
| `deepseek_client.py` | `stream_chat()`，thinking / reasoning_effort |
| `kline_features.py` | 逐棒几何特征（内包/外包、ii/iii 等） |
| `prompts/schemas.py` | Stage1/2 JSON Schema 定义 |

### 4.4 编排层 `pa_agent/orchestrator/`

| 文件 | 职责 |
|------|------|

**Stage 2 重要策略**：`STAGE2_VALIDATION_AUTO_RETRY = False` — 校验失败**不会**自动重调 API。

### 4.5 GUI 层 `pa_agent/gui/`

**侧栏 Tab**：实时 | 决策树 | 决策树可视化 | 决策 | 未来走势 | 原始 | 调试

### 4.6 记录与经验 `pa_agent/records/`

## 5. 核心数据流（提交分析）

```
用户点击「提交分析」
    │
    ▼
MainWindow 暂停图表刷新 → 构建 KlineFrame（snapshot.py）
    │
    ▼
_AnalysisWorker（后台线程）→ TwoStageOrchestrator.submit()
    │
    ├─ require_active_license()（仅打包版）
    ├─ PreflightDataGate：≥20 根已收盘 + 指标有效？
    │       └─ 否 → 落 partial，不调 AI
    ├─ Stage1：PromptAssembler.build_stage1() → DeepSeekClient.stream_chat()
    ├─ JsonValidator.validate("stage1") → normalize_stage1
    ├─ route_strategy_files() → ExperienceReader.read_for_stage2()
    ├─ gate 短路？→ 跳过 Stage2 API
    ├─ Stage2：build_stage2_continuation() → stream_chat()
    ├─ JsonValidator.validate("stage2") → normalize_stage2
    ├─ PendingWriter.save_full() → records/pending/*.json
    ├─ PositionTracker.apply_decision()
    └─ NotificationService（按配置推送）
    │
    ▼
GUI 更新：DecisionPanel、Chart overlay、AIStreamPanel
```

**事件机制**：编排器通过 `OrchestratorEvent`（Stage1Started、Stage1Done、RecordSaved 等）驱动 UI 更新；`EventBus` 用于记录保存广播。

## 6. 策略路由（Stage 2 加载哪些 txt）

入口：`pa_agent/ai/router.py` → `route_strategy_files(stage1_json)`

**输入字段**：`cycle_position`、`direction`、`detected_patterns`、`spike_stage`、`alternative_cycle_position`

**逻辑概要**：

1. 按 `cycle_position` × `direction` 选基座文件（通道 / 极速 / 震荡区间）
2. 按 `detected_patterns` 叠加专项文件（楔形、H1H2、铁丝网、磁力位等）
3. `extreme_tr` / `unknown` → 返回空列表（不建议交易）
4. 去重后返回文件名列表，由 `PromptAssembler` 加载

**Stage 1 固定注入**（不走路由）：`市场诊断框架.txt`、`文件16-K线信号识别.txt`、`逐棒分析检查单.txt` 等。

完整文件清单见 `prompt_engineering/` 目录。

### Settings 五大块

```python

    provider: AIProviderSettings,      # model, base_url, api_key, thinking, context_window
    general: GeneralSettings,          # 品种/周期/数据源/decision_stance/keep_analysis
```

`AnalysisRecord`（`records/schema.py`）核心字段：

| 字段 | 含义 |
|------|------|

## 14. 风险与边界（交接必知）

1. **非交易系统**：无任何券商 API；`positions/` 仅为软件内跟踪。
2. **Windows 优先**：MT5、DPAPI 授权依赖 Windows；Mac 见 `MAC版本智能体部署方法.txt`。
3. **提示词即业务**：大量领域逻辑在 txt 中，改 Python 前确认是否应改 prompt。
4. **Stage2 不重试**：校验失败不会自动重调模型，需从 prompt 或 normalizer 修。
5. **settings.json 损坏**：有备份机制；删除后可重建默认配置。
6. **AGPL-3.0**：分发修改版需遵守开源义务。
